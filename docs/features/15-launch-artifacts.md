## TLDR

- Current behavior: doc 15 covers the launch proof artifacts (spec 11.4, M9). `shipgrade
  demo --format html --out <path>` writes a self-contained HTML report by reusing the
  existing `render_html` renderer over the frozen demo report. `examples/sample-report.html`
  is committed as the byte-identical output of that command and is the standalone proof a
  reader sees without running anything. The README "Sample output" block (spec 11) is the
  unedited `shipgrade demo` stdout, asserted byte-for-byte against the live command in CI, so
  the HTML, the README block, and the demo all show the same Grade F / 13 / 100 result. A
  second artifact, the real-world proof gallery under `examples/real-world/`, grades three
  regulated-domain prompts (one real CC0-licensed public prompt and two illustrative authored
  ones) in `prompt_file` mode; it is generated once with a judge key and committed static.
- Core invariants: the `html` branch reuses `render_html`, never a new renderer; the
  committed sample equals `render_html(make_demo_report())` exactly; the demo is
  deterministic (frozen `started_at`); the default text demo and its snapshot are unchanged;
  the html emit writes no badge and sends nothing externally.
- Verification: `tests/test_sample_report_stable.py` (the emit path, the byte-for-byte match
  to the committed sample, the documented-render equality, the self-contained checks, and the
  default-demo-writes-no-html guard); `tests/test_readme_sample_verbatim.py` (the README
  "Sample output" block equals the live `shipgrade demo` stdout byte-for-byte); the existing
  `tests/test_demo_offline.py` and the report snapshots stay green; `./verify.sh`.
- Known gaps (deferred, spec 11.4 / 11.6): the demo GIF, the social-preview image
  (`docs/assets/social-preview.png`), and the launch-evidence packet
  (`docs/launch-evidence/`) are launch-time artifacts captured outside the build and do not
  gate the release. They are out of this task; only the committed HTML and its emit command
  ship here.

## Public Interface

The `demo` command gains two options (`src/shipgrade/cli.py`):

- `--format {cli,html}` (default `cli`). `cli` prints the report to the terminal (the
  existing behavior). `html` writes one self-contained HTML file and returns.
- `--out PATH` (default `None`). The output path for `--format html`. When omitted with
  `--format html`, the file is written to `./shipgrade-report.html`. Ignored by `--format
  cli`.

`render_html(report: Report, waivers: list[Waiver] | None = None) -> str` is reused
unchanged from `src/shipgrade/report/html.py`. The demo emit passes no waivers.

The documented regeneration command for the committed deliverable is:

    shipgrade demo --format html --out examples/sample-report.html

## Output surface

- `--format html`: writes the HTML file and prints one line, `Wrote <path>`. No badge, no
  scan, no network.
- `--format cli` (default): unchanged. Prints the auditing banner, the rendered CLI report
  (Grade F / 13 / 100), writes `.shipgrade/badge.json`, and prints the CI follow-up lines.
- `examples/sample-report.html`: a self-contained HTML document (inline CSS, no external
  assets), the byte-identical default-demo output, committed as a docs deliverable.

## Business Rules

- The committed `examples/sample-report.html` MUST equal `render_html(make_demo_report())`
  byte-for-byte. CI asserts this, so a stale sample fails the build instead of drifting from
  the README excerpt and the demo (spec 11.4 drift lock).
- The HTML is deterministic because `make_demo_report` freezes `started_at` to
  `2026-06-01 12:00:00` (spec 7.2) and the template interpolates only that date. There is no
  `datetime.now()` in the demo render path.
- The default text demo path is byte-identical to before this feature: the new options
  default to `format=cli`, `out=None`, so `render_cli(report)` and its `13/F` snapshot are
  untouched.
- An unknown `--format` value is a usage error (`typer.BadParameter`, exit 2), consistent
  with the spec 5.6 exit-code contract.

### Real-world proof gallery (`examples/real-world/`)

A second committed artifact (spec 11.4) demonstrates shipgrade on regulated-domain prompts,
not just the bundled demo. Layout: `prompts/<slug>.txt` holds each system prompt;
`configs/<slug>.yaml` is the scan config (`prompt_file` mode, a repo-root-relative `ref`,
`probe_packs: [owasp-core-v1]`, one domain rule pack, `outputs: [cli, html, json]`);
`<slug>.html` and `<slug>.json` are the committed graded reports; `README.md` carries the
provenance table and methodology. Three targets cover the three rule packs: one real,
CC0-licensed public prompt (`financial-analyst-template`, finance) for provenance and two
illustrative authored prompts (`health-triage-assistant`, health; `homework-tutor`,
education) clearly labeled as not real products.

- The gallery is generated once with a judge key (`shipgrade scan` in `prompt_file` mode
  sends the prompt to a provider), then committed static. It is never wired into the offline
  `demo`, the demo-grade gate, or any CI byte-comparison test, so no CI test needs a live
  key and the demo stays offline and key-free.
- The reports are point-in-time snapshots from a non-deterministic judge; a re-run can
  differ. They are not asserted byte-stable (unlike `examples/sample-report.html`).
- Every grade is framed as an automated heuristic audit, not a certification and not a
  verdict on any product or author. The one real prompt is reproduced under CC0 1.0 with its
  source URL and retrieval date recorded; the authored prompts are marked illustrative.
- The gallery ships publicly through the `examples/` whole-directory allowlist (spec 11.2);
  `tests/test_public_boundary.py` and `scripts/build-public-tree.test.sh` prove it is
  token-clean and shipping. It adds no probe, OWASP category, model, or `Finding` field.

## Public boundary verifier

`scripts/check-public-boundary.sh <tree-dir>` is the operationalized spec 11.2 pre-push
checklist. The launch runbook runs it FROM the workshop AGAINST the candidate orphan public
tree (the clean tree built at push time, not the workshop itself) before any push:

    bash scripts/check-public-boundary.sh <public-tree>

It exits 0 when the tree is clean and exits 1 after printing every violation found. It
fails when private career-strategy material is present in the candidate tree; it does not
bless the workshop, where private files are tracked by design (the design spec, root
`CLAUDE.md`, `.codex/`). Point it only at the candidate public tree.

Two checks run, both reporting every hit rather than stopping at the first:

- Presence: any of these existing in the tree is a violation. Root `CLAUDE.md`, root
  `AGENTS.md`, `.claude/agents/`, `.claude/rules/agent-dispatch.md`, `.codex/`,
  `docs/superpowers/`, `build-specs.md`, `hormozi/`, plus the verifier itself
  (`scripts/check-public-boundary.sh`) and its test (`tests/test_public_boundary.py`).
- Tokens: a recursive `grep -rIiE` (skip binary, case-insensitive, extended regex) for the
  forbidden career-strategy patterns. The multi-word patterns are separator-insensitive (a
  `[ _-]?` between words), so a phrase is caught whether it is space-, hyphen-, or
  underscore-joined, because the private files use more than one separator form for the same
  phrase. A hit in any file is a violation. The patterns themselves are not listed here:
  this doc is public, and spelling out a live token would make the doc fail its own gate.

The script and its test never enter the public tree: they are themselves on the denylist
above. The script's source literally contains the forbidden tokens, so publishing it would
publish the secrets it guards, which is why the script also checks for ITSELF in the
candidate tree. Both are excluded from the public allowlist and the script depends only on
bash, grep, and find.

`tests/test_public_boundary.py` verifies the gate by building a real public subset (copy of
the spec 11.2 allowlist items that exist, minus the test itself) and asserting it passes;
adding a root `CLAUDE.md`, a clean-named file carrying a forbidden token, or the verifier
itself each makes the gate fail.

## Failure Modes

| Scenario | Behavior | Recovery |
| --- | --- | --- |
| `--format` is neither `cli` nor `html` | `typer.BadParameter`, exit 2 | Pass `--format cli` or `--format html`. |
| `--out` points at a missing parent directory | `write_text` raises `FileNotFoundError`, exit 1 | Create the parent directory first (the documented command writes under existing `examples/`). |
| Committed sample drifts from the renderer | `test_committed_sample_is_the_documented_demo_render` fails in CI | Regenerate with the documented command and commit the result. |
| A public file carries a forbidden token | `scripts/check-public-boundary.sh` exits 1, naming the file and token | Remove the token from the public file before the push (do not weaken the token list). |
| The boundary verifier is run against the workshop, not the candidate tree | It fails on the tracked private files, as designed | Point it at the candidate orphan public tree, not the workshop. |

## Edge Cases

- `--format html` with no `--out`: writes `./shipgrade-report.html`.
- `--format cli` with `--out`: `--out` is ignored; the text report prints as usual.
- No API key set: irrelevant; the demo is offline and key-free in both formats.
